Executed plan

  1. Stabilize the engine. Centralize interaction transitions, cancellation, visibility and disposal; preserve existing API and add explicit workspace/assembly options.
  2. Make the playground coherent. Persistent workspace/collection controllers, synchronized controls, compact tuning, meaningful help and copy fallback; consolidate CSS.
  3. Package an independent library. Structural stylesheet, typings, minimal example, current API documentation, agent guide and package/site allowlists.
  4. Verify and measure. Deterministic regressions, actual browser integration, compact/reduced-motion checks, source gzip accounting and a reproducible local frame benchmark.
  5. Prepare a release artifact. Static Pages build, manual deployment workflow, MIT/asset notices and an explicit alpha limitation list. Do not publish until separately requested.

Acceptance gates

  • Focused path cards stay on the path after drag and dismissal.
  • Pointer cancellation, visibility changes, pause and disposal stop owned animation work.
  • Native controls remain usable; keyboard operation, compact layout and reduced motion remain available.
  • A separate example runs with only source modules and structural CSS.
  • Documentation and declarations match actual methods, options and limitations.
  • The package excludes screenshots, tests, demo assets and local reports; the Pages artifact contains only intended public files.

What changed

  • Engine: one scene owner per element, constant document gesture listeners, pointer cancellation and interruption cleanup, preserved belt identity, explicit pause/resume, offscreen/hidden suspension, complete RAF/animation statistics, precise authored-DOM restoration and reusable assembly slots.
  • Workspace: resize and focus feedback, semantic compaction before scaling, public content/summary wrappers, centered assembly, and narrow-screen document flow that overrides authored canvas height.
  • Playground: persistent workspace and collection controllers, synchronized settings, visible arrangement choices, progressive tuning/help, native study dialogs, setup export and clipboard fallback.
  • Integration: standalone CSS and two independent examples, TypeScript declarations, current documentation, agent guide, package exports and explicit asset notices.
  • Release preparation: validated static build, generated canonical/social/structured metadata and sitemap, package allowlist, actual tarball installation test, and a manually triggered Pages workflow.

Collection interaction refinement

Grid rows now have an approximately 54px desktop gutter and open in overview. Pile drags cycle behind the stack by default, with a curved return and a free-placement toggle; cancelled or stationary gestures preserve order. Belt and figure-eight layouts expose cursor steering, smooth centre braking, reversal, adjustable tilt and optional hover-to-pause or continuous cruising. Nine controller regressions cover these behaviors. Earlier benchmark numbers above are retained as the baseline run, not a fresh measurement of this refinement.

Practical examples and product page

Added a curved fan, a snapping review rail with keyboard navigation and bounded drag momentum, and a closed spiral path. Creative studies, a launch checklist and original reading notes reuse the same six panels while preserving demo-owned completion state across arrangements. The landing page uses an animated three-plane identity and family previews. Its full-bleed hero is an automatic five-chapter showreel: orbit, spread, stack, focus and flow. One set of live DOM cards is continuously rearranged; manual chapter and pause controls remain available. Card interaction now gives a small local tilt and scale response while the reel continues uninterrupted. Only the explicit Pause control stops playback. Decorative clipping no longer creates an internally scrolling hero. A 390px layout has no horizontal overflow; the illustrative hero scales its spatial composition while the full playground keeps native controls in a readable stack.

Attention research

The pointer-only Attention gallery has been removed from the shipped playground. Its prototype is retained separately until real eye tracking is implemented and validated. The research note remains available for provider selection, calibration and pilot planning. No actual gaze performance is claimed.

Release sequence

  1. Completed: engine stabilization and independent integration contract.
  2. Completed: accessible playground pass, documentation, deterministic regressions, Chromium integration and reproducible diagnostics.
  3. Completed: MIT package and GitHub Pages build artifact. Local server is available on port 4414.
  4. Before broader compatibility claims: run the harness and manual tasks in Safari and Firefox, then on physical midrange phones. Validate keyboard/screen-reader tasks and browser zoom with real application content.
  5. When publication is requested: create/configure the public repository, verify the intended URL, manually deploy the prepared Pages workflow, check live links/assets/metadata, and add the new sitemap to the host site. npm naming and publication remain separate decisions.

After this pass

Physical midrange phones, Safari/Firefox, browser zoom and assistive-technology task testing remain necessary before a broad compatibility or performance claim. Test task completion against a flat layout. Do not promise universal 60fps, zero overlap for arbitrary content, npm availability or public indexing before the evidence exists.
